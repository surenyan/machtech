# machtech
Օգտագործել եմ Gemini AI 60 տողից բաղկացած սինթետիկ CSV ֆայլ (raw_orders.csv) գեներացնելու համար, որպեսզի չօգտագործեմ իրական հաճախորդների տվյալներ։ Ֆայլում ներառվել են սխալներ validation-ը ստուգելու նպատակով:
Աշխատանքը կատարել եմ PostgreSQL-ում։ ստեղծեցի առանձին error_log view, validation-ն ու error log-ը անելու համար։Սրա միջոցով տվյալների ձեռքով ստուգում չի արվել ու պրոցեսը ավտոմատացել է: Տվյալների մաքրումը և Status-ների մափինգը նույնպես արվել է SQL մակարդակում (cleaned_orders view), որպեսզի վերլուծության (ագրեգացիայի) փուլ անցնեն միայն ճիշտ տվյալները:
Տվյալների cleaning-ը ու mapping-ը․ ստեղծել եմ cleaned_orders view-ն որպեսզի մինչև ագրեգացիաներ անելը, հարցումը ավտոմատ ֆիլտրի բոլոր սխալ տողերը (բացասական գները կամ սխալ էլ. հասցեները) և status_id-ները (1, 2, 3) փոխվել է տեքստային արժեքներով (Pending, Shipped, Delivered) որ հետո Dashboard-ում լինեն միայն ճիշտ տվյալներ:
Քանի որ առաջադրանքում կոնկրետ ագրեգացիոն ցուցանիշներ նշված չէին ես ընտրել եմ հետևյալները․
Եկամուտ ըստ ապրանքի- ցույց է տալիս թե որ պրոդուկտներն են հիմնական շահույթ տալիս։
Պատվերների ստատուս- լոգիստիկ նպատակով, օր կան արդյոք pending պատվերներ։
